# P0-001 — Capture reproducible baseline

Status: **REVIEW**
Roadmap phase: **P0 — Stabilize, contain, and establish truth**
Depends on: **none**
Product behavior changed: **no**

## Objective

Create a deterministic, source-controlled baseline of the current Kristin repository: source tree, schema set, tool registry identity, test/gate inventory, CI definition, current CI failures, release classification, and content hashes.

## Acceptance criteria

1. `baseline.json` and `BASELINE.md` are byte-reproducible from the committed source manifest and observation snapshot.
2. `execution.json` explicitly distinguishes `passed`, `failed`, `unavailable`, and `not_run`.
3. A complete checkout can verify every entry in `SOURCE_MANIFEST.sha256`.
4. Snapshot-only execution cannot be mistaken for source verification.
5. Missing Flutter/Dart or missing gate scripts are recorded as unavailable, never passed.
6. The capture tool is dependency-free, bounded, redacts common credential patterns, and runs no product commands unless `--run-safe-gates` is selected.
7. Unit tests cover manifest validation, deterministic output, source mismatch, explicit unavailability, registry inspection, and redaction.

## Implementation

- Added `tool/capture_baseline.py`.
- Added `tool/capture_baseline_test.py`.
- Added committed observation input at `release/evidence/baseline/observations.json`.
- Added the production roadmap at `docs/KRISTIN_GOLD_STANDARD_PRODUCTION_ROADMAP.md`.
- Added minimal roadmap state at `docs/roadmap/STATUS.md`.
- Generated deterministic baseline and machine-execution evidence.
- Updated `SOURCE_MANIFEST.sha256` for new source inputs; generated evidence remains intentionally outside that source-input manifest to avoid self-referential hashing.

## Reproduction

```bash
python3 -m unittest -v tool/capture_baseline_test.py
python3 tool/capture_baseline.py \
  --project . \
  --manifest-mode verify \
  --run-safe-gates \
  --strict
```

A manifest-only reviewer may run:

```bash
python3 tool/capture_baseline.py --project . --manifest-mode snapshot
```

That second command must record source verification as `unavailable`.

## Current execution limitation

The patch preparation environment had Python and Git but no Dart or Flutter, and it did not contain a complete project checkout. The implementation and its fixture-based tests were executed, while full checkout and SDK gates are explicitly unavailable in the generated execution report. This task must remain in **REVIEW** until the patch is applied to the repository and a clean-checkout run passes source verification.
