# P0-006 — Protect repository governance

## Status

REVIEW

## Objective

Protect the GitHub default branch so changes require a pull request, documented solo-maintainer review, the three mandatory desktop status checks, resolved conversations, linear history, and force-push/deletion protection.

## Dependencies

- P0-003 — must contain a same-commit passing Ubuntu/Windows/macOS CI matrix through native build.

## In scope

- CODEOWNERS;
- pull-request and issue templates;
- machine-readable governance policy;
- local governance contract tests;
- guarded GitHub ruleset and label applicator;
- merge policy documentation;
- task and evidence records.

## Out of scope

- bypassing or weakening a failing P0-003 check;
- guessing status-check names from a failed run;
- fabricating an independent reviewer or approval;
- silently changing repository visibility, billing, collaborators, or organization membership;
- signing-key policy, which belongs to later release-supply-chain work.

## Acceptance criteria

- [ ] P0-003 CI matrix is `passed` for the current commit.
- [ ] CODEOWNERS covers all source and security-critical paths.
- [ ] PR template requires roadmap, platform, authority, test, evidence, and review information.
- [ ] Desired ruleset has no bypass actors.
- [ ] Default branch requires a pull request, durable solo-maintainer attestation, and all mandatory CI checks.
- [ ] `validate-ubuntu`, `validate-windows`, and `validate-macos` are required and strict.
- [ ] Force pushes and deletion are blocked.
- [ ] Merge commits are disabled; squash/rebase remain available.
- [ ] Labels exist.
- [ ] A blocked-merge and allowed-merge test PR are recorded.
- [ ] No token or credential appears in source, logs, or evidence.
- [ ] Solo-maintainer review attestation passes.
