# P0-003 — Green the current three-OS CI

## Status

REVIEW

## Objective

Make the existing Ubuntu, Windows, and macOS workflow reach and pass every current gate while preserving truthful platform capability semantics. This task repairs the failed first integration attempt, canonicalizes the Dart source, and produces platform evidence. It does not redesign CI, pin toolchains, implement Owner Mode, or fabricate a sandbox.

## Dependencies

- `P0-001` — complete on the integration branch.
- `P0-002` — `v1_trust_disabled` is active and the eight-case attacker-forgery gate passes.

## Integration failure findings

| ID | Failure | Root cause | Repair |
|---|---|---|---|
| `P0-003-WIN-001` | `ModuleNotFoundError: resource` on Windows | `tool/sandbox_worker.py` imported the POSIX-only module at module load | Guard the import, require the module for Linux backend readiness, and fail closed in `_apply_limits` |
| `P0-003-DART-001` | Generated v170/v180/v190 contracts did not parse | JSON Schema keys such as `$id`, `$schema`, `$ref`, and `$defs` were emitted into ordinary Dart strings without escaping `$` | Add one shared Dart literal encoder, repair all generators, regenerate all outputs, and add a negative gate |
| `P0-003-DART-002` | `durable_workflow.dart` did not parse | SQLite JSONPath `$.snapshotSha256` was embedded in a Dart multiline string without escaping interpolation | Emit `\$.snapshotSha256` in Dart source, preserving `$.snapshotSha256` at runtime |
| `P0-003-FMT-001` | Formatting changed many files and then stopped | The source was not canonically formatted and syntax failures occurred mid-run | Fix syntax first; run one explicit formatter pass; keep every verification command non-mutating |
| `P0-003-SDK-001` | `flutter_lints` include could not be resolved | Some local/release gates formatted before `flutter pub get` | Resolve dependencies before format/analyze/test; use `--no-pub` downstream |
| `P0-003-CI-001` | The first starter could emit malformed workflow nesting | YAML insertion used indentation-sensitive text blocks without a structural guard | Insert steps inside `jobs.validate.steps` and reject two-/four-space escaped step markers in the executable repair gate |
