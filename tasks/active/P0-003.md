# P0-003 — Green the current three-OS CI

## Status

IN_PROGRESS

## Objective

Make the existing Ubuntu, Windows, and macOS workflow reach and pass every current gate while preserving truthful platform capability semantics. This milestone fixes the current formatting failure and the Windows Project Manager/SDK-environment regressions; it does not redesign CI, pin the toolchain, implement Owner Mode, or fabricate a sandbox.

## Dependencies

- `P0-001` — baseline implementation present; formal closure receipt should be preserved.
- `P0-002` — `v1_trust_disabled` is active and the attacker-forgery gate passes.

## Authority impact

- No access profile is widened.
- No project command is allowed to fall back to the host.
- Built-in packaging is classified as `host_snapshot_no_project_code_execution`.
- Synthetic CLI and SDK environment probes use `execution_mode="host"` because they execute fixed test code written by the test itself, not repository/project code selected by a model.
- Owner Mode remains future work.

## In scope

1. Canonically format the current Dart source.
2. Make format verification non-mutating.
3. Classify built-in snapshot packaging independently from sandboxed project execution.
4. Make Project Manager tests capability-aware:
   - exercise the real sandbox when available;
   - assert `project_action_blocked` + `sandbox_unavailable` otherwise;
   - verify no project mutation/artifact is recorded after a blocked action.
5. Run synthetic CLI profile and SDK environment probes explicitly as trusted-host fixtures.
6. Preserve the 16-case Project Manager gate while making each result semantically truthful.
7. Run every downstream workflow step on all three operating systems.
8. Record redacted evidence and update roadmap status.

## Required implementation

### A. Built-in package readiness

When `package` has no project-defined command, readiness must be:

```json
{
  "state": "ready",
  "reasons": [],
  "backend": "builtin_snapshot_packager",
  "assurance": "host_snapshot_no_project_code_execution"
}
```

This path may snapshot, hash, ZIP, and persist evidence. It must not launch project code.

A project-defined package command remains sandbox-dependent.

### B. Sandbox-dependent test contract

For Analyze/Test/Build/Run:

```text
sandbox available
→ execute the existing real sandbox behavior
→ verify output, retained workspace, artifacts, and process-tree lifecycle

sandbox unavailable
→ call the real public operation
→ require project_action_blocked
→ require sandbox_unavailable in reasons
→ require source tree unchanged
→ require no fabricated artifact/process success
```

### C. Trusted-host test probes

The synthetic custom-profile probe and SDK-environment probe must create a `CommandSpec` with:

```text
execution_mode = host
```

Only fixed code constructed inside the offline test may use this path. The product default remains `sandbox`.

### D. Verification semantics

`verify.sh` and CI must check formatting without modifying files. Run a separate explicit formatting command once before committing.
