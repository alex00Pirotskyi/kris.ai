# P0-007 — Split source lint from behavioral assurance

## Status
DONE

## Objective

Create a machine-enforced assurance taxonomy so source-marker checks, executable behavioral tests, SDK/toolchain checks, platform evidence, and release evidence are reported separately.

## Dependencies

- P0-001 — reproducible baseline

## In scope

- Reclassify `tool/system_test.py` as source-contract inspection.
- Add assurance metadata to `tool/validate_release.py` checks.
- Prevent source and mixed checks from contributing to pure behavioral totals.
- Produce categorized JSON and Markdown assurance reports.
- Add executable regression tests for overclaim detection.
- Integrate the gate into verification and CI without weakening P0-002 or pending P0-003 behavior.

## Out of scope

- Rewriting every legacy mixed test into a separate executable harness.
- Claiming native platform, sandbox, installer, update, or release assurance.
- Changing product runtime behavior.
- Completing P8-001's full test hierarchy.

## Required implementation

1. Add `tool/assurance_model.py`.
2. Add `tool/architecture_contract_test.py`.
3. Add `tool/assurance_dashboard.py`.
4. Add `tool/assurance_model_test.py`.
5. Add `tool/p0_007_assurance_test.py`.
6. Add `schemas/assurance_report.v1.json`.
7. Reclassify `tool/system_test.py` output.
8. Categorize every validator check and fail on unknown classifications.
9. Integrate tests and dashboard into `tool/verify.sh` and CI.
10. Regenerate `SOURCE_MANIFEST.sha256`.

## Required tests

- Source-only pass does not set behavioral assurance to passed.
- Mixed pass does not set behavioral assurance to passed.
- Pure executable behavior can set behavioral assurance to passed.
- Source or mixed overclaim is detected and fails strict reporting.
- Unknown checks fail classification.
- `system_test.py` reports `behavioralProof: false`.
- Dashboard contains distinct assurance sections.
- P0-002 trust disablement remains present when it existed before application.

## Acceptance criteria

- [ ] Dashboard never reports source-marker checks as behavioral proof.
- [ ] `system_test.py` is explicitly source-contract-only.
- [ ] Every validator check has a non-ambiguous category.
- [ ] Mixed checks are visible but excluded from behavioral totals.
- [ ] Strict reports fail on unknown classification or overclaim.
- [ ] Complete-checkout commands pass.
- [ ] Independent review reports no critical/high finding.
