# Kristin Local Agent v1.1.4+114 deterministic release-test hotfix

## Reported workstation result

The v1.1.3 Windows source passed the authoritative application gates:

- `flutter analyze --no-pub`: no issues;
- `flutter test --no-pub`: 88 tests passed;
- `kristin test --system`: 9 passed, one optional parser skip, zero failures.

A subsequent `kristin test --release` reached the same Flutter test suite but failed inside the mock Ollama cold-load retry fixture with:

```text
model_load_timeout: Ollama could not finish loading tiny-model after 2 bounded attempts.
```

No production Ollama instance or real model was involved. `tiny-model` is the local HTTP fixture used by `execution_reliability_test.dart`.

## Root cause

The fixture gave every preload attempt only 40 milliseconds. It delayed the first mock response for 90 milliseconds to force a timeout, then expected the second localhost request to connect, be scheduled, read, and complete inside the same 40-millisecond deadline. That race can pass on an idle machine and fail after repeated analysis, tests, and packaging activity.

The cancellation fixture used a similar fixed 50-millisecond sleep before cancelling. Fixed sleeps test scheduler luck rather than the intended state transition.

## Corrections

### Explicit retry handshake

The first preload response now waits for the server to observe the second preload request. Because the second request cannot be sent until the first attempt times out, the first timeout is deterministic. Once the retry reaches the server, the second response completes immediately.

The local fixture timeout is two seconds. This remains short while allowing normal Windows scheduling and antivirus activity.

### Explicit cancellation handshake

The cancellation test now waits until the mock server has received the preload request before completing the cancellation signal. It no longer assumes that 50 milliseconds is enough for every workstation.

### Deterministic Kristin test gates

Flutter tests launched by Kristin use:

```text
flutter test --no-pub --concurrency=1
```

The release validator uses the same single-worker policy. Direct developer invocations may still choose Flutter's default concurrency.

### Actionable failure summaries

When a Flutter test fails, the CLI preserves the line identifying the failing test alongside the most relevant exception. A provider exception can no longer hide which fixture produced it.

## Security and runtime scope

This release does not broaden project permissions, model permissions, filesystem access, network access, or process execution. Production Ollama preload, timeout, retry, cancellation, and keep-alive behavior is unchanged. The source changes are limited to deterministic test synchronization, release-test scheduling, diagnostic summarization, contracts, metadata, and documentation.

## Verification

Run on Windows:

```powershell
dart format .
dart format --output=none --set-exit-if-changed .
flutter pub get
flutter analyze --no-pub
flutter test --no-pub --concurrency=1
.\kristin.cmd test --system --project .
.\kristin.cmd test --release --project .
flutter run -d windows
```
