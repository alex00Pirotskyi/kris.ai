# v0.9.3+93 Memory relevance and agent-action recovery hotfix

This source-preview release addresses behavior observed in real project runs where generic work-item text dominated retrieval and failed run episodes were repeatedly injected into new agent context.

## Retrieval behavior

Automatic work-item retrieval now searches with the original user request. It does not append deterministic plan titles such as `Inspect project and establish evidence baseline`.

For normal execution, only successful run episodes are eligible for automatic context. Failed, cancelled, and interrupted episodes become eligible when:

- the user request explicitly asks about failures, errors, timeouts, debugging, retries, previous runs, or run history; or
- the episode was explicitly pinned by the user.

The Knowledge UI, governed tool, and API continue to support explicit inspection of unsuccessful history. When it is included, outcome-aware weighting and episode diversity prevent failed runs from occupying every result slot. Knowledge-index schema 3 stores the terminal episode outcome and automatically rebuilds old caches.

Episode index text is also normalized so `Failure`, `Lessons`, `Failed work`, and `Changed files` are not repeated in the same citation snippet.

## Agent response recovery

Kristin still requires one governed JSON action per model turn. The parser now accepts common equivalent shapes emitted by local and OpenAI-compatible models, including:

- `tool_call`, `call_tool`, `function_call`, and implicit objects containing a tool name;
- `answer`, `response`, `done`, and other completion aliases;
- `input`, `parameters`, `args`, and JSON-encoded function arguments.

An unsupported or malformed response no longer ends the work item immediately. Kristin records a response hash and received object shape, returns strict schema feedback to the model, and permits two correction turns. After three invalid responses, the run fails with a targeted diagnostic that recommends checking Logs or selecting a stronger instruction-following model.

No raw model response is copied into the failure memory by this repair path.

## Conversational fast path

Simple greetings and capability questions are classified as Ask even when the composer is in Auto mode. They create one `Respond conversationally` item with no project tools and start immediately because there is no sensitive action to review. Contract revision 2 ensures previously prepared v0.9.2 inspection plans are not reused for the same request after upgrade.

For this no-tools item only, a bounded non-empty ordinary-text model response is accepted as the completion summary when the model ignores the JSON envelope. This fallback cannot select a tool, obtain a permission, or mutate the project.

## Timeout adjustment

Default model deadlines are now:

- model discovery/load: 3 minutes;
- response start: 5 minutes;
- total response: 15 minutes.

Agent action output is bounded to 4,096 tokens. These values improve cold-start behavior for slower local models without permitting unbounded generations.

## Verification

Behavioral tests cover:

- successful-only automatic episode retrieval;
- explicit diagnostic retrieval of failed episodes;
- de-duplicated failed-work snippets;
- common local-model action variants;
- greeting plans that contain no inspection item or tool access.

The offline release validator also rejects regressions in the safe retrieval policy, command revision, action-repair loop, and conversational plan.
