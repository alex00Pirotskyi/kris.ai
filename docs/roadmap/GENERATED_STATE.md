# Generated-state policy

**Policy version:** `2.0.0`
**Milestone:** `P0-010`
**Authority:** `tool/source_tree_policy.py`

Kristin keeps source inputs, reviewed generated contracts, and durable milestone evidence separate from disposable workstation output.

## Source inputs that remain committed

The policy does **not** remove or ignore:

- generated Dart contracts under `lib/product/generated/`;
- `pubspec.lock`, `.metadata`, schemas, migrations, and fixtures;
- benchmark baselines under `evals/results/`;
- reviewed evidence under `release/evidence/<task-id>/`;
- manually authored reports that do not match a generated-output pattern.

These files are reproducible or reviewable source inputs even when a generator originally created them.

## Disposable generated state

The policy excludes:

- Python bytecode and test/type/lint caches;
- Flutter/Dart package state and native ephemeral output;
- compiled build, coverage, IDE, and operating-system state;
- Node/package-manager caches;
- Playwright browsers, reports, traces, profiles, downloads, and test output;
- automation-host build/cache output;
- dataset build intermediates;
- generated evidence staging directories;
- timestamped `reports/kristin-test-*` output;
- root-level release reports regenerated by verification, including SBOM, secret scan, validation, architecture, and assurance reports.

## Commands

Audit the current checkout:

```bash
python3 tool/generated_state_guard.py audit --project . --strict
```

Explain classifications:

```bash
python3 tool/generated_state_guard.py explain \
  tool/__pycache__/x.pyc \
  lib/product/generated/v190_contracts.g.dart
```

Prove that a test sequence did not introduce non-generated changes:

```bash
python3 tool/generated_state_guard.py snapshot \
  --project . \
  --output release/evidence/generated/before.json

# Run the desired tests here.

python3 tool/generated_state_guard.py verify-clean \
  --project . \
  --baseline release/evidence/generated/before.json
```

The snapshot files live under an ignored generated-evidence directory. They are not milestone evidence.

## Removal rules

The P0-010 applicator removes only paths classified by the new policy. Before deletion it copies existing content to an external sibling backup. It never follows symlinks during cleanup.

A path that is still listed by the Git index but has been deleted from the worktree is reported as `trackedGeneratedPendingDeletion`. This state is acceptable while reviewing the patch. After commit, CI must report no tracked generated paths at all.

## Benchmark integration

When P0-009 is present, P0-010 regenerates the portable baseline and records the before/after delta. The expected product change is that `path_safety.generated_state_policy` moves to `passed`. P0-010 rejects any regression in a previously passing benchmark case.

## Future extension

P9-002 may extend this policy after the real automation host, browsers, and dataset pipeline exist. It must preserve one shared policy used by validation, scanning, packaging, benchmarks, and release tooling.
