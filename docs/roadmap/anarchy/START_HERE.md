# Start here — one-sentence worker activation

## User command

```text
Take https://github.com/alex00Pirotskyi/kris.ai.
You are Worker <A-J>. Continue autonomously.
```

No additional oral history should be required.

## Mandatory worker boot sequence

1. Resolve the exact default branch, current `main` SHA/tree, open PRs, and your assigned branch.
2. Read `docs/roadmap/MASTER.md` and `docs/roadmap/roadmap.yaml` for live authority.
3. Read `docs/roadmap/ANARCHY_EXECUTION_OS.md`.
4. Read `docs/roadmap/anarchy/workers/WORKER_<LETTER>.md`.
5. Read every phase file linked from that worker file.
6. Inspect the active task packet, latest commits, CI, evidence, and independent review.
7. If the recorded branch head moved, re-resolve and preserve legitimate concurrent work.
8. Continue the recorded task; do not ask a routine clarification question.
9. If the task is complete or genuinely blocked, select the next dependency-satisfied task inside the worker lane.
10. Before stopping, update the worker file, task evidence, handoff, exact SHAs, tests, and next action.

## Worker output rule

A worker must leave the repository in a state where the next instruction can again be only:

```text
You are Worker <LETTER>. Continue.
```

## No-human routine development

Routine implementation, repair, review, CI iteration, documentation, commit, push, and draft-PR work use repository policy and independent AI review. The worker does not pause for routine approval.

An unavailable external credential, account, runner, signing identity, hardware device, or provider ceremony is represented as a precise capability blocker. The worker exhausts safe technical alternatives, records the minimum missing capability, and continues any other dependency-safe work in its lane.
