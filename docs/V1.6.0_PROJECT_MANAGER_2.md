# Kristin v1.6.0 capability layer — Project Manager 2

The v1.6 capability layer is implemented inside the canonical v1.7 source head. It converts the project dashboard concept into an executable, fail-closed operations service rather than a report-only design.

## Implemented boundary

Project Manager 2 provides:

- strict `kristin.project.json` profile parsing through `schemas/project_profile.v2.json`;
- detected Analyze and Test commands for supported source profiles;
- live sandbox capability probing before an action can be marked ready;
- read-only workspaces for Analyze and Test;
- retained, integrity-checked snapshots for Build, Run, and Package;
- durable `project_profiles`, `workspace_sessions`, `managed_project_processes`, and `artifact_records` tables;
- bounded artifact discovery and presence, text, JSON, ZIP, image, and directory validation;
- sandboxed finite actions and managed Run/Stop over the complete PID-reuse-safe descendant tree;
- abrupt-launcher-death cleanup through Linux parent-death signaling and namespace-child termination;
- stale-process reconciliation;
- deterministic source packaging;
- CLI status, execute, start, process-status, and stop operations;
- a generated Project Manager snapshot contract.

The operative readiness rule is:

```text
profile request
∩ deterministic policy
∩ live worker capability
= executable action
```

A profile cannot authorize unsandboxed host execution, unsupported network access, secret use, port publication, traversal paths, absolute paths, shell wrappers, or unknown authority-bearing fields.

## Persistence

SQLite workflow migration 5 adds the Project Manager records in the same transactionally governed database used by the durable run kernel. Project Manager does not create a competing mutable JSON store.

## Executable gate

`tool/project_manager_v2_test.py` covers 16 cases, including real Analyze, Test, and Build operations in temporary projects, source-tree immutability, retained snapshot output, managed Run/Stop, abrupt launcher death, zero surviving sandbox descendants, artifact persistence, deterministic packaging, and append-only intelligence records.

## Honest boundary

This source includes the Linux worker backend. Native Windows and macOS isolated workers, worker-to-host preview-port forwarding, native folder-picker tests, and the complete Flutter desktop UI integration remain unverified or unavailable. Unsupported operations fail closed.
