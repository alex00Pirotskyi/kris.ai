# Kristin Local Agent v1.0.7+107 failed-run recovery hotfix

## Diagnostic input

The analysis used `kristin-diagnostics-1784482690475.zip` (SHA-256 `47bb8141259ce002e51f4d3ea4857cce4836e29cc15c039d1f38e5443d6454d5`). The archive was structurally safe and its internal manifest passed. The recorded product version was `1.0.4+104`.

Affected run: `run_hkjnl5dagrldsloYB4qnRQTS3h`. The selected model was Ollama `phi4-mini:latest` (3.8B, Q4_K_M). The run consumed six model requests and five repairs, executed zero tools, and ended with `model_protocol_exhausted`.

## First causal event

The calculator request mentioned calculation history, error handling, validation, and testing. The previous failed-memory classifier treated generic application vocabulary as failed-run diagnostic intent. Automatic knowledge evidence therefore recorded `includeUnsuccessfulEpisodes: true` and injected eight failed episodes. Several contained the old work-item label `Inspect project and establish evidence baseline`.

The model then returned variants of that label as the `action` value, sometimes with a `[K8]` task identifier. The coordinator correctly rejected the noncanonical action, but its repair example was selected alphabetically from allowed tools instead of being selected for the task. The model copied the same historical phrase until the bounded repair budget was exhausted.

## Other contributing defects

- The generated information task instructed the agent to search online, but did not allow research tools.
- The product was configured in local-only mode, so live web research and public deployment were unavailable regardless.
- The generated plan referenced external GUI/design and browser-testing services that the runtime cannot directly operate.
- The active project path appeared to be Kristin’s own source checkout rather than a separate calculator project.

## Corrections

1. **Strict unsuccessful-memory opt-in.** Failed/interrupted/cancelled episodes are eligible only when `includeUnsuccessfulEpisodes` is explicitly true or the episode is pinned. Retrieval no longer infers permission from query words.
2. **Contextual diagnostic classifier.** Failed memory is enabled automatically only for explicit historical run/attempt/task investigation, not ordinary product error handling or history features.
3. **Task-aware protocol normalization.** The exact observed composite action is converted to `knowledge_search` for an information task when that tool is already allowed. No permission is added by the adapter.
4. **Task-aware repair and fallback.** Protocol repair examples choose `knowledge_search`, `list_directory`, `index_project`, or `git_status` according to the work item instead of alphabetical order.
5. **Anti-copy schema rule.** The model is told not to place work-item titles, task IDs, `[K#]` citations, or prior-run text in the `action` field.
6. **Capability-aligned planning.** Local-only plans remove live-research tools, add local knowledge where appropriate, produce project-local design artifacts instead of claiming external GUI use, and convert public deployment into a bounded local preview plus deployment package/manual hosting instructions.
7. **Self-project guard.** Build/fix plans cannot target a checkout identified as Kristin’s own source.
8. **Better diagnostics.** Exported summaries now include automatic memory policy and model-protocol recovery sections.

## Security behavior

The compatibility adapter can select only a tool already in the work item’s allowlist. Failed-memory exclusion cannot hide pinned evidence from an explicit user investigation. Path, permission, mutation, process, network, secret, and transaction controls remain enforced by the coordinator.

## Upgrade behavior

Install v1.0.7 in a clean source folder, select a separate application project folder, and regenerate the prompt and plan. Do not Retry the historical failed run because its plan and evidence are immutable diagnostic history.
