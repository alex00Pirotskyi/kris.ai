# Kristin Local Agent v1.1.0+110 Project Manager preview

Version 1.1.0 adds a simpler project-centered workspace and repairs the capability mismatch found in diagnostic run `run_hkk9czt4wzMPTp3bsaqLnpNOx2`.

## Project Manager workspace

The **Project Manager** tab is the operational home for a selected project. It presents one shared project profile and the actions most users need:

- **Doctor** checks the folder, detected project type, toolchain, model state, and available commands.
- **Analyze** runs the detected static-analysis or lint command.
- **Test** runs the detected bounded quick-test sequence.
- **Build** runs the detected build command.
- **Run** starts the project as a managed child process.
- **Stop** terminates the managed process with a grace period and forceful fallback.
- **Ask Kristin** opens project-scoped chat.
- **Open Runs** shows agent task progress and evidence.
- **Save logs** exports a redacted diagnostic ZIP.

The page also shows the detected Analyze, Test, Build, and Run commands, recent agent runs, process ID, current status, bounded live output, and the managed log filename.

The desktop UI, loopback API, and CLI use the same `ProjectExecutionProfile`. A custom project can define commands in `kristin.project.json`:

```json
{
  "type": "Custom web application",
  "analyze": {"executable": "npm", "arguments": ["run", "lint"]},
  "test": {"executable": "npm", "arguments": ["test"]},
  "build": {"executable": "npm", "arguments": ["run", "build"]},
  "run": {"executable": "npm", "arguments": ["run", "dev"]}
}
```

Review custom commands before executing them. Project Manager processes run with the desktop user's operating-system privileges in this source preview. Managed-process tracking is session-local; after an application or operating-system crash, verify and stop any orphaned preview process manually.

## API

The authenticated loopback API adds:

```text
GET  /v1/projects/{projectId}/manager
POST /v1/projects/{projectId}/analyze
POST /v1/projects/{projectId}/test
POST /v1/projects/{projectId}/build
POST /v1/projects/{projectId}/run
POST /v1/projects/{projectId}/stop
```

Read access requires `projects:read`; operational actions require `projects:execute`.

## CLI

```powershell
.\kristin.cmd doctor  --project .
.\kristin.cmd analyze --project .
.\kristin.cmd test --quick --project .
.\kristin.cmd build    --project .
.\kristin.cmd run      --project .
.\kristin.cmd run      --project . --execute
```

The default `run` command is a dry run. `--execute` starts the process in the foreground; Ctrl+C stops it.

## Capability-aligned task compilation

The compiler now derives effective execution mode from the task's promised work rather than trusting only the model's top-level mode label.

A task that promises to create or modify a file, feature, design artifact, implementation, test, package, or deployment output receives only the mutation tools already registered and governed by Kristin. The compiled command receives project-write permission through the normal approval flow.

An explicitly planning-only task remains read-only. Phrases such as “plan only” and “do not implement” prevent accidental promotion.

Wireframe and user-flow tasks are normalized to a project-local artifact such as:

```text
docs/design/wireframes.md
```

Equivalent duplicate local-deployment tasks are removed during normalization.

## Mutation evidence

Artifact-producing build and fix tasks cannot report success without a recorded project mutation. Kristin gives the model at most two dedicated mutation-correction turns per attempt and emits:

```text
work_item.mutation_required
```

If the task reaches its turn limit without a required mutation, it now fails with:

```text
implementation_stalled_read_only
```

This is more actionable than a generic agent-turn failure and preserves the remaining run budget.

## Security boundary

The new Project Manager and plan compiler do not allow the model to authorize tools or permissions. Existing project boundaries, approval scopes, stale hashes, transaction handling, redaction, process limits, and evidence requirements remain active.
