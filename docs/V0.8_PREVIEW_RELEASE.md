# v0.8.0+80 Chat Workspace preview

## Release intent

This release implements the highest-value portion of the product strategy that can be delivered safely as a source update in one engineering pass: a comprehensible chat-first surface, visible execution progress, project diagnostics, prompt management, local research memory, and usable debugging views.

It deliberately does not claim to be the completed production-hardening program.

## Implemented

### Chat-first product shell

- One conversation composer for questions, creation, fixes, research, review, and run requests.
- Chats and Projects as the only primary destinations.
- Runs, Prompt Studio, Knowledge, Skills, and Logs in a collapsible Build & Debug section.
- Responsive sidebar/drawer behavior and status strip.
- Inline task contract summary, proposed work items, grouped permissions, task start, work-item timeline, run controls, completion summary, and evidence.
- Slash commands for common destinations and diagnostics.

### Observable runs

- Historical/current run selection.
- Pan-and-zoom graph built from the execution-plan dependency graph.
- Node state, attempts, duration, inputs, outputs, evidence, and related events.
- Pause, resume, cancel, and retry controls using the existing governed coordinator.
- Simple, technical, and raw JSON log views with filtering.

### Project diagnostics

- Native folder-selection attempts on Windows, macOS, and common Linux desktops.
- Automatic profiles for Flutter, Dart, Node.js, Python, Go, Rust, .NET, Maven, Gradle, CMake, static websites, and custom profiles.
- Model-independent Doctor inspection.
- Bounded Quick Test commands with captured, redacted output.
- Cross-platform standard-library Python CLI and wrappers.

### Prompt Studio

- Persistent prompt records in `state/prompts.json`.
- Title, description, system and user templates, variables, tags, command mode, and version.
- Prompt preview and insertion into a new chat.
- Audit events for saves and deletion.

### Research and knowledge

- Fetched research records include raw fetched content, selected response headers, status, redirects, hashes, extracted text, and timestamps.
- Source and search-result JSON snapshots are archived per project under `research-archive`.
- Search results are added to project-scoped knowledge.
- Knowledge UI supports search, notes, source visibility, and deletion.

### File foundation

- `inspect_file` provides bounded inspection, type detection, metadata, SHA-256, text preview, or a bounded base64 preview.
- `write_binary_file` performs bounded base64 decoding and transactional project mutation.
- Existing text/source and deployment tooling remains available.

### Persistence and release quality

- Persistent collection updates now hold one in-process lock across read, modify, and atomic write.
- Active Dart allowlists include the new files.
- Source tests and release gates assert the v0.8 Chat Workspace contract.
- Deterministic source packaging includes an embedded manifest and release metadata.

## Not implemented in this preview

- OS-enforced sandboxing for project commands, build tools, or MCP servers.
- SQLite migration, full multi-process locking, or database migrations.
- Fully crash-journaled file transactions across every power-loss window.
- Complete DNS-pinned SSRF protection.
- Signed or externally anchored audit records.
- Strict allowlist-only support bundles.
- Signed desktop installers, platform notarization, or authenticated updates.
- Autonomous self-modification or automatic promotion of learned skills.
- Universal file conversion and generation for every format.
- Complete-site crawling or copying remote databases.

## Validation performed for this source package

- All active Dart files parsed with a Dart tree-sitter grammar without syntax errors.
- Python tooling compiled successfully.
- Deterministic architecture, active-tree, security-invariant, Chat Workspace, hygiene, SBOM, and secret-scan gates passed.
- `kristin test --quick` passed its source/security checks.
- ZIP integrity, path safety, embedded manifest coverage, and SHA-256 checks are verified during packaging.

Flutter and Dart SDK executables were not installed in the build environment. Therefore `dart format`, `flutter pub get`, `flutter analyze`, `flutter test`, and a native desktop build were unavailable. The package is correctly classified as a **source release**, not a compiled application.

## Recommended next increment

1. Run full Flutter validation on Windows, macOS, and Linux and fix any SDK/API issues.
2. Ship a normal Windows installer and signed binaries.
3. Introduce an OS sandbox worker before expanding autonomous execution.
4. Replace JSON repositories with SQLite and explicit migrations.
5. Add behavioral integration tests for first launch, project creation, model setup, read-only chat, mutation rollback, restart recovery, research archive, and run graph updates.
