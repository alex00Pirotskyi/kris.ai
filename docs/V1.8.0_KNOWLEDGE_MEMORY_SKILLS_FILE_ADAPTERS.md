# Kristin v1.8.0+180 — Knowledge, memory, skills, and file adapters

## Scope of this release

This release advances the roadmap-correct v1.8 milestone by adding the safest foundation pieces first:

- content-addressed object storage for immutable knowledge and skill payloads;
- strict memory-admission and quarantine policy;
- freshness-aware cited retrieval for research evidence;
- deterministic skill-candidate extraction and approval-gated publication;
- a governed file-adapter registry with native and sandboxed-core tiers.

It keeps the verified v1.2–v1.7 cumulative foundations intact.

## Implemented

### Content-addressed object store

`lib/product/knowledge_memory_v2.dart` and `tool/knowledge_memory_v2.py` provide a deterministic object store rooted at `support/objects/sha256/<ab>/<cd>/<hash>`.

It deduplicates identical bytes, writes sidecar manifests, and is used for new skill-candidate and published-skill payloads. The same path pattern is available to future research and artifact captures.

### Memory admission and quarantine

A terminal run is no longer assumed to be useful memory automatically.

`MemoryAdmissionPolicy` now classifies episodes as:

- `admitted` — successful governed work with evidence;
- `quarantined` — unsuccessful diagnostic memory that must not silently influence ordinary retrieval;
- `rejected` — conversational or evidence-free material.

Pinned memory remains available by explicit user choice.

### Research freshness and citation controls

`ResearchFreshnessPolicy` labels retrieved evidence as `fresh`, `aging`, or `stale` based on capture age.

Cited context blocks now include:

- capture timestamp;
- freshness label;
- explicit citation rule;
- trust boundary warning for external sources.

### Skill candidates and publication

Successful admitted episodes can produce deterministic `SkillCandidateRecord` objects. Publication remains explicit:

- replay must pass;
- approval note is required;
- candidate tools cannot expand beyond governed allowlists;
- publication emits a stable manifest hash.

### Core file adapters

`lib/product/file_adapters.dart` and `tool/file_adapters.py` add a governed registry with:

- native adapters for text, JSON, YAML, XML, CSV, images, and ZIP;
- sandboxed-core adapters for PDF, DOCX/XLSX/PPTX, ODT, RTF, EPUB, and RFC822 email;
- deterministic detection, inspection, and bounded reopen validation.

This is not yet universal file conversion. It is the governed adapter foundation required before broader format expansion.

## Qualification boundary

This is a validated source release. Flutter/Dart SDK-dependent UI and native desktop gates remain unavailable in this environment.
