# Kristin Local Agent v1.0.1+101 model-protocol hotfix

## Reported failure

A governed run reached its model-decision step and failed with:

```text
work_item_failed: model_action_invalid:
The model must return action=tool, complete, or fail.
```

The subsequent `memory.episode_recorded` event was expected: it recorded the already-failed run for diagnostics. It was not the cause of the failure.

## Root cause

The v1.0 coordinator accepted the canonical action schema and several aliases, but some local models returned semantically equivalent actions in response envelopes or field layouts that were not recognized. Examples include snake-case `function_call`, `tool_input`, `action_input`, chat-completion wrappers, double-encoded JSON, ReAct action blocks, explicit allowed tools paired with nonstandard action verbs, and semantic names such as `inspect_project`.

The repair counter was also cumulative across the full work item. A valid response did not clear an earlier malformed-response streak, so intermittent protocol mistakes could eventually exhaust repair attempts.

Model evidence retained a cryptographic hash but no bounded response preview, which made the exact incompatibility difficult to diagnose from Logs.

## Repair

v1.0.1 introduces a bounded `AgentProtocolAdapter` that:

- unwraps known model and chat-completion envelopes to a maximum depth;
- accepts canonical JSON, fenced/prose JSON objects, double-encoded JSON, and bounded ReAct action blocks;
- normalizes common completion and failure labels;
- resolves safe tool aliases only when exactly one target is already present in the work item allowlist;
- normalizes common argument aliases without executing them;
- rejects tools outside the allowlist before the governed tool registry is reached;
- leaves every permission, path, stale-hash, transaction, process, secret, network, and evidence check unchanged.

After two consecutive invalid responses, an inspection/evidence-baseline item may perform one bounded read-only `list_directory` or `index_project` fallback if that tool is already allowed. The fallback cannot write files, run commands, connect to the network, or add a permission. A second exhausted sequence produces `model_protocol_exhausted` with non-content diagnostics.

## Diagnostics

Model evidence now records:

- provider and exact model identity;
- timing and token counters;
- response SHA-256 and character count;
- a redacted response preview capped at 2,000 characters.

Events include:

- `model.protocol_repair_requested`;
- `model.protocol_fallback_applied`;
- `model.protocol_exhausted`.

The global event stream keeps hashes, action/tool metadata, and candidate keys rather than the full model response. The bounded preview remains in the evidence record.

## Regression coverage

Behavioral fixtures cover:

- snake-case `function_call`;
- `tool_calls` and chat-completion wrappers;
- double-encoded response objects;
- safe tool and argument aliases;
- explicit allowed tools with nonstandard action verbs;
- nested completion payloads and boolean completion signals;
- ReAct-style actions;
- rejection of a disallowed tool.

The offline system and release validators require these protections before packaging.
