# Kristin Local Agent v1.1.7+117 — Stability Freeze and Golden Replay Baseline

## Release purpose

This release starts the Product-Grade V2 roadmap with the smallest architectural slice that directly prevents the two supplied production failures. It intentionally does not introduce broad new product surfaces. Its mission is to make known execution failures reproducible, classify their causal state transitions, and convert them into deterministic release gates.

## Exact causal chain

1. The model emitted a valid `write_file` intent but wrapped the entire project path in Markdown backticks: `` `docs/design/wireframes.md` ``.
2. v1.1.6 preserved the content, but path normalization treated the backticks as literal filename characters.
3. Windows therefore created a directory whose first component began with a backtick and a file whose name ended with a backtick.
4. The literal mutation path did not equal the canonical expected artifact path `docs/design/wireframes.md`.
5. Artifact mutation-required state and product-specific validation were bypassed because the coordinator believed the expected artifact still had not been affected.
6. Recovery remained read-oriented. The run repeatedly used `knowledge_search`, `inspect_file`, and `list_directory` instead of correcting the exact artifact.
7. Some model outputs copied coordinator-history metadata, including a shape equivalent to `{"action":{"toolRepair":true,"turn":7}}`, as though it were a new action.
8. Attempt one consumed ten of twelve repair credits. Attempt two began with only two credits, insufficient for protocol, tool-input, and verification correction.
9. A repeated inspection was redirected to another read-only listing even though a mutation was required.
10. A later write targeted the same literal backtick path and became a no-op. The run ended with 59 model-request credits still available but no repair credits.

The terminal message described a repair-budget failure. The first causal defect was path-token canonicalization; the convergence policy and retry-budget policy then amplified it.

## Implemented controls

### Exact whole-scalar path-token canonicalization

`canonicalModelPathToken` removes only presentation wrappers that surround the complete scalar value:

- an exactly matched run of one to three Markdown backticks;
- matching single quotes;
- matching double quotes.

It then passes the result through the existing workspace-boundary rules. Traversal, NUL, outside-project paths, unsupported schemes, and symbolic-link or reparse-point escapes remain blocked. Canonicalization does not grant new filesystem authority.

The function is applied before:

- provider argument alias normalization;
- workspace path policy;
- artifact-path matching;
- mutation-path extraction;
- external-path classification;
- prior-evidence reconstruction.

### Bounded artifact mutation recovery

For an explicitly named Markdown design artifact that already has an objective `ArtifactEvidencePolicy` validator, repeated read-only discovery can now change strategy to a deterministic, task-specific `write_file` action.

The policy is deliberately narrow:

- the task must require validated artifact evidence;
- `write_file` must already be allowed by the approved work item;
- an explicit expected artifact path must exist;
- no permission is widened;
- an unobserved canonical target is created with `expectedExists=false`, so recovery cannot overwrite an existing file;
- an inspected target carries both `expectedExists=true` and its `expectedSha256`, so replacement fails closed on state drift;
- the generated content is tied to the approved product context and validator coverage.

For the calculator diagnostic, the recovery draft covers arithmetic operators, pointer/touch and keyboard parity, real-time results, history, undo/redo, responsive states, interaction states, accessibility, error behavior, and implementation handoff.

### Automatic post-mutation verification

After a material mutation affects an expected validated artifact, the coordinator now performs one deterministic `inspect_file` call on that exact canonical path. The inspection:

- consumes normal governed tool budget;
- records evidence and events;
- feeds the objective artifact validator;
- can complete the work item without another model request;
- fails visibly if the inspection itself fails.

New events include:

```text
work_item.artifact_auto_inspection_started
work_item.artifact_auto_inspection_completed
work_item.artifact_auto_inspection_failed
```

### Retry repair reservation

A new `RunRetryBudgetPolicy` requires at least four repair credits before another work-item attempt may start. This reserve is intended to cover a meaningful combination of protocol repair, tool-input repair, and objective verification correction.

At the observed v1.1.6 state—10 repairs used out of 12—the retry is rejected as `insufficient_repair_reserve` rather than starting a doomed attempt.

### Non-copyable coordinator history projection

Raw correction records are projected into bounded instruction objects. Discriminator, turn, and repair-counter fields are removed from model-visible history, and the prompt explicitly prohibits copying history or emitting coordinator metadata such as:

```text
historyType
coordinatorCorrection
toolRepair
protocolRepair
turn
counter fields
```

Only the canonical tool, complete, or fail action schemas are valid outputs.

```powershell

```

The ordinary quick source gate also executes the compact replay corpus.

## Why the current terminal run cannot be resumed in place

The run record is already terminal and its immutable event history accurately records v1.1.6 behavior. Changing that record would destroy diagnostic provenance. The supplied archive is redacted and does not include the physical `test88` project tree, so this source release cannot safely rename or delete the literal backtick path on the user’s machine.

Use a fresh v1.1.7 run after reviewing the project-local recovery steps in `docs/CURRENT_RUN_RECOVERY.md`.

## Scope intentionally deferred

This release does not claim completion of the whole V2 roadmap. The following remain separate architecture programs:

- SQLite event history and crash-safe workflow reconstruction;
- side-effect idempotency across process or machine failure;
- OS-level sandbox workers, network broker, and secret broker;
- complete JSON Schema generation for every tool and provider;
- independent role-based model routing and verifier service;
- full semantic progress ledger across all artifact and criterion types;
- Project Manager 2 and Prompt Studio 2 redesign;
- native Windows, macOS, and Linux compile/installer qualification.

The environment used to prepare this source release did not contain Dart or Flutter. Native `dart format`, `flutter analyze`, `flutter test`, and Windows execution remain authoritative on a configured workstation.
