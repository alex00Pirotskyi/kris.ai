# Kristin Local Agent v1.0.3+103 agent-loop recovery hotfix

## Reported failure

A local model repeatedly requested the same successful project-root listing. Kristin correctly detected stagnation, but v1.0.2 treated the third identical result as terminal even though the run retained most of its model and tool budget:

```text
agent.stalled_repeated_tool_outcome
work_item.attempt_failed
work_item.retry_skipped
run.failed
```

The run-memory event that followed was a consequence of the failure, not its cause.

## Root cause

The v1.0.2 guard compared successful read-only tool outcomes and stopped after the configured repetition limit. It prevented unbounded budget consumption, but it had no recovery phase between detection and failure. A weaker local model could therefore remain trapped on `list_directory` even though the coordinator already had enough information to choose a safer next evidence action.

## v1.0.3 behavior

### Duplicate reads are not dispatched twice

Within one work-item attempt Kristin fingerprints each successful static read using:

- exact governed tool name;
- canonical arguments;
- the current mutation epoch.

When the model requests the same tool and arguments again without an intervening Kristin mutation, the coordinator reuses the recorded result. The duplicate request consumes the model turn that produced it, but it does not consume another tool call or repeat the underlying filesystem, index, Git, knowledge, or research operation.

Event:

```text
agent.repeated_tool_call_blocked
```

The event records action and outcome fingerprints, repetition count, cached result summary, recovery decision, and current budgets.

### Bounded read-only progress substitution

After blocking a duplicate, Kristin may substitute one different action only when all of the following are true:

- the replacement tool is already allowlisted for the current work item;
- the tool is read-only;
- the action remains inside the active project boundary;
- the action has not already been used as a loop-recovery step;
- the repair budget remains available.

Preferred recovery order is:

1. inspect a safe project descriptor or source entry point from the existing directory listing;
2. build the bounded project index;
3. collect bounded Git status;
4. collect one root listing if none has yet succeeded.

Event:

```text
agent.loop_recovery_redirected
```

### Sensitive-path exclusion

Automatic file-selection excludes:

- hidden path segments;
- `.env`-like names;
- secret, credential, password, token, private-key, API-key, and `id_rsa`-like names;
- files larger than 2 MiB;
- deep or unsupported paths.

Preferred safe files include `README.md`, `pubspec.yaml`, `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, build manifests, and common entry points.

### Deterministic evidence-baseline completion

Only the dedicated read-only work item whose title or description identifies an **inspect-project evidence baseline** can complete without another model response.

Completion requires diverse objective evidence:

- one successful directory listing;
- at least one successful `read_file` or `inspect_file` result containing a SHA-256;
- either independent structural evidence from `index_project`, `git_status`, or `git_diff`, or a second independently hashed file.

The coordinator creates a grounded summary containing the recorded entry count, relative file paths, SHA-256 values, and structural evidence type.

Events:

```text
agent.loop_recovery_completed
work_item.evidence_baseline_completed
```

The first is used when repetition recovery was involved. The second is used when the model naturally gathered diverse baseline evidence.

### Explicit non-goals

This mechanism cannot:

- answer a general project question on the model's behalf;
- complete implementation, mutation, test, verification, research, or deployment work;
- add a tool or permission;
- inspect a path outside the project;
- bypass stale-file hashes, transactions, approvals, budgets, or audit logging;
- turn a failed tool result into success.

If the model continues repeating after all safe unused recovery actions are exhausted, Kristin still raises `agent_stalled_repeated_tool_outcome` and preserves the remaining run budget.

## Diagnostics

Saved diagnostic ZIPs now include an **Agent loop recovery** section in `run-diagnostic-summary.md`. It lists:

- duplicate requests that were blocked;
- cached outcome fingerprints;
- substituted tools and relative arguments;
- baseline auto-completion decisions;
- terminal loop decisions when recovery was unavailable.

The complete redacted event timeline and bounded model-response evidence remain included. Diagnostic archives can still contain project-confidential context and must be reviewed before sharing.

## Regression coverage

The release adds behavioral contracts for:

- redirecting a repeated root listing to `inspect_file`;
- choosing `README.md` before unrelated files;
- excluding `.env` from deterministic inspection;
- refusing baseline completion without diverse evidence;
- completing after a root listing, SHA-256-backed inspection, and project-index evidence;
- refusing deterministic completion for `Answer from grounded context` work items;
- retaining terminal repeated-loop protection as the last resort.
