# Kristin Local Agent v1.1.6+116 execution-reliability redesign

## Executive conclusion

The supplied failure is not primarily a calculator-design problem and not simply a weak-model problem. It is a coordinator/protocol defect amplified by a small local model and an inefficient recovery loop.

The decisive defect was in `AgentProtocolAdapter._normalizeArguments`. The model returned a usable nested `write_file` action with `filePath` and a substantial `content` string. The adapter recovered the tool name and translated `filePath` to `path`, but its alias search omitted the canonical key `content` itself when that field was placed directly inside the nested `action` object. `workspace_tools.dart` then treated a missing content field as an empty string and successfully created a zero-byte Markdown file.

After that false success, the coordinator repeatedly asked the model to inspect the same empty file. The artifact validator correctly rejected the empty artifact, but the repair prompt did not enforce a mutation before another inspection. Nine model calls consumed 702,821 ms (11.71 minutes) to produce only 1,824 response characters, while seven repairs and nine tool calls never changed the zero-byte artifact after its initial creation.

V1.1.6 fixes the causal chain rather than increasing retry budgets.

## Root-cause chain

1. **The model used a tolerated but noncanonical envelope.**

   It returned:

   ```json
   {
     "action": {
       "type": "write_file",
       "filePath": "docs/design/wireframes.md",
       "content": "# Interactive Web Application Wireframe ..."
     }
   }
   ```

2. **The protocol adapter lost a canonical field.**

   `_normalizeArguments` searched aliases such as `text`, `body`, and `fileContent`, but not `content` itself in the nested action container. Similar omissions existed for `path`, `query`, `url`, `executable`, `args`, `processId`, and other canonical fields.

3. **The write tool converted malformed input into a successful empty mutation.**

   `_writeFile` used `arguments['content']?.toString() ?? ''`. Missing content therefore became a valid empty write instead of `argument_required`.

4. **The validator detected the bad artifact but recovery was not stateful.**

   Artifact validation saw no inspectable content. The coordinator added a natural-language correction, but it did not mark the artifact as requiring mutation and did not block another inspection.

5. **The model entered a low-information repetition attractor.**

   The 3.8B model repeatedly selected the simplest allowed action—inspect the named file—because each turn included a large task contract, full plan, and expanding history but no hard state transition requiring a write.

6. **Retry budgets amplified the defect.**

   Repairs and second attempts replayed the same impossible state instead of changing strategy. More budget produced more latency, not more capability.

## Other recurring failure modes

The retained diagnostics show that the same architectural pattern appears in several forms:

| Failure family | Observed examples | Architectural problem |
|---|---|---|
| Protocol normalization | `model_action_invalid`, `model_protocol_exhausted`, missing `executable`, missing `path` | The adapter accepted many envelope shapes but did not preserve all canonical nested arguments or provide machine-readable required fields. |
| Invented paths | `/home/username/project/...`, `path_outside_project`, `path_absolute_rejected` | The safety boundary worked, but recovery repeatedly delegated path correction to the same model instead of re-anchoring read-only exploration to the selected root. |
| Non-convergent loops | repeated tool outcome, repair-budget exhaustion, turn-limit exhaustion | Recovery was phrased as advice, not represented as coordinator-owned state with allowed next transitions. |
| Model-service limits | load timeouts and generation timeouts | The selected model and hardware can be slow; large repeated prompts made the problem worse. |
| Planning/policy mismatch | self-project target rejection and overbroad early design tasks | Some failures are safe policy outcomes, but plan compilation should surface them before execution and avoid making optional design documentation a hard blocker for implementation. |

## Implemented redesign

### 1. Lossless protocol normalization

Canonical target keys are now included in nested argument recovery. A direct nested `content` field remains `content`; a direct nested `path` remains `path`; the same rule applies to query, URL, binary content, replacement fields, expected hashes, process fields, and command arguments.

A regression test uses the exact envelope observed in the diagnostic bundle and verifies that both `docs/design/wireframes.md` and the full content string survive parsing.

### 2. Fail-closed write semantics

`write_file` now distinguishes:

- missing `content`: hard `argument_required` error with `details.argument = "content"`;
- explicitly supplied empty content: allowed, because an intentionally empty file can be valid;
- complete content: normal atomic write.

This prevents malformed model output from becoming a destructive or misleading success.

### 3. Machine-readable tool contracts

Tool descriptors now expose `argumentSchema` with:

- required fields;
- optional fields;
- canonical examples.

The execution prompt tells the model to put all parameters inside `arguments` and to include every required field. `write_file` is explicitly documented as requiring both `path` and `content`.

### 4. Stateful artifact repair

The coordinator reconstructs known artifact state from retained evidence and tracks artifacts that require mutation.

When an expected artifact is empty or incomplete:

- the path and observed hash are recorded;
- another `read_file` or `inspect_file` for that same path is blocked;
- the next permitted transition is an allowed mutation action;
- the model receives a canonical `write_file` example with the exact path and expected hash;
- the event `work_item.artifact_mutation_required` is emitted.

This changes recovery from “please try something better” to an explicit state-machine transition.

### 5. Deterministic workspace re-anchoring

When the model invents an unresolved external path for a read-only action, Kristin no longer spends several model calls asking it to repair the path. If `list_directory` is allowed, the coordinator safely substitutes a bounded listing of `.` and records the strategy as `external_read_root_fallback`.

External writes and genuine cross-project paths remain blocked.

### 6. Idempotent desired-state completion

A correct pre-existing artifact may now complete after inspection even when no write was needed in the current run. Kristin reports that the artifact was validated rather than pretending it was created.

Empty or incomplete artifacts still require mutation. This avoids unnecessary rewrites, backups, hash churn, and mutation-budget consumption.

### 7. Product-specific artifact coverage

Calculator evidence now recognizes both named and symbolic arithmetic operations and checks request-dependent coverage for:

- keyboard input;
- touchscreen interaction;
- real-time results;
- editable/copyable result fields;
- calculation history;
- undo and redo;
- responsive states, interaction states, and accessibility.

### 8. Lower-latency execution prompts

The execution loop no longer sends the entire serialized contract and entire plan on every turn.

It now sends:

- a compact contract summary;
- current plan position and dependencies;
- at most eight remaining work items;
- bounded recent evidence;
- bounded tool-result payloads;
- a 24,000-character history ceiling instead of 60,000.

Execution temperature is fixed at `0.0`, and nonconversational output is capped at 2,048 tokens rather than 4,096. A single action JSON should not reserve essay-sized output capacity.

### 9. More precise repair messages

`argument_required` recovery is now keyed by the missing argument:

- missing content → write the complete content before inspecting again;
- missing path → use `.` or the exact project-relative artifact path;
- missing executable → provide one program and a JSON args array;
- other missing arguments → follow the descriptor schema.

## Redesigned execution workflow

The recommended runtime is a coordinator-owned state machine rather than an unconstrained ReAct loop:

```text
PREPARE
  → validate selected workspace and model capability
  → compile smallest executable work item

OBSERVE
  → inspect only evidence needed for the current item
  → cache observation fingerprints

DECIDE
  → model chooses one typed action from the current state's legal transitions

NORMALIZE + VALIDATE
  → preserve nested canonical arguments
  → enforce required fields before dispatch
  → re-anchor safe read-only invented paths

ACT
  → execute one governed tool
  → journal mutation/no-op/error truthfully

VERIFY
  → coordinator validates the declared artifact or test result
  → complete deterministically when acceptance criteria are met

REPAIR
  → convert failure into a specific next-state constraint
  → block transitions already proven unproductive
  → retry only when the next attempt has materially different state

ESCALATE
  → stop with a precise model/workspace/tool recommendation when no safe transition remains
```

## Recommended next architecture phases

### Phase A — included in this patch

- Lossless nested-argument normalization.
- Required-argument schemas and examples.
- Fail-closed writes.
- Mutation-required artifact state.
- Safe root fallback for invented read paths.
- Compact prompts, bounded history, deterministic decoding.
- Idempotent artifact completion.
- Diagnostic-derived regression tests.

### Phase B — next priority

1. **Coordinator-owned post-mutation verification.** Automatically inspect a named artifact after a successful write instead of spending a model turn asking what to do next.
2. **Capability-aware model routing.** Parse parameter size/context limits and warn or route complex build plans away from models below a configurable capability threshold.
3. **Plan criticality.** Mark work items as `required`, `verification`, or `optional`. Optional wireframes must not block implementation unless the user explicitly asks for design deliverables.
4. **Phase-local budgets.** Allocate budgets to observe, mutate, and verify phases. Never let read-only exploration consume the mutation/verification reserve.
5. **Semantic progress ledger.** Record facts such as `artifact_exists`, `artifact_empty`, `artifact_missing_fields`, and `tests_failed` instead of relying on raw message history.
6. **Repair effectiveness gate.** A retry is allowed only when its prompt, tool allowlist, workspace anchor, or evidence state differs from the failed attempt.

### Phase C — robustness and utilization

1. JSON Schema-constrained generation for providers that support it.
2. Automatic work-item splitting when a small model stalls on a high-entropy task.
3. Model-call cache keyed by compact state, not full prompt text.
4. Per-stage latency telemetry: prompt evaluation, first token, generation, tool execution, and verification.
5. Failure-class dashboards that separate safety rejections, infrastructure failures, model capability failures, and coordinator defects.
6. Replay tests that run recorded model envelopes through the protocol and coordinator without invoking a model.

## Expected operational effect

For the supplied focus run, the causal behavior changes as follows:

- the first nested write preserves its content instead of creating a zero-byte file;
- a missing-content write cannot report success;
- an empty inspection requires a mutation and cannot be repeated indefinitely;
- a model-invented external read path is re-anchored to the selected workspace without another model call;
- each subsequent prompt is materially smaller;
- correct pre-existing artifacts do not need pointless rewrites.

The patch does not make a 3.8B model equivalent to a large coding model, and it cannot eliminate hardware/model load timeouts. It does ensure that coordinator defects no longer erase valid model output or turn one malformed action into minutes of repeated failure.
