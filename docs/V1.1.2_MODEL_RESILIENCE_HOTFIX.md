# Kristin Local Agent v1.1.2+112 model resilience hotfix

## Diagnostic finding

The supplied diagnostic archive records run `run_hkkkbh7q3rNkIqtjzJuPYvsiiy` on v1.1.1+111. The selected Ollama model was `phi4-mini:latest` (3.8B, Q4_K_M). The first work item made one model request, waited 180,138 ms, used no tools or mutations, and failed with `model_load_timeout` while 79 of 80 model requests remained.

The old provider treated one HTTP-response deadline as the model-load deadline. It did not explicitly preload the selected model, did not retry a transient cold load inside the same agent turn, and did not close the provider HTTP client when the user stopped a run.

The same generated task plan contained another latent contradiction: a local-only task instructed Kristin to recruit users and collect feedback even though the task had no human-study capability and only local tools. That task would have failed or fabricated progress after the model-load problem was cleared.

## Provider repair

V1.1.2 separates local-model availability from response generation:

1. Resolve the exact selected Ollama model.
2. Preload it with a bounded non-streaming `/api/generate` request containing an empty prompt.
3. Keep the model loaded for a configurable period.
4. Retry one transient cold-load failure inside the same model request, so no additional agent turn or model-request budget is consumed.
5. Do not multiply an exhausted provider cold-load retry through another complete work-item retry.
6. Start the normal bounded NDJSON generation stream after the preload succeeds.
7. Apply separate load, first-token, and total-generation deadlines.
8. Close the active HTTP client when the run is stopped or cancelled.

Defaults:

```text
Cold-load deadline:  480 seconds
Cold-load retries:   1
Keep-alive:          15 minutes
First-token timeout: 5 minutes
Generation timeout:  15 minutes
```

The AI Models settings page exposes the load deadline, retry count, and keep-alive within bounded ranges.

## Progress and diagnostics

Runs can now retain stage events such as:

```text
model.load_started
model.load_retry_started
model.load_retry_scheduled
model.load_completed
model.generation_started
```

The diagnostic ZIP summary includes **Model availability and cold-load recovery**, with attempts, duration, selected model, and final outcome. Stop cancellation is distinguishable from a timeout.

## Capability-safe plan normalization

Generated non-manual tasks receive at least two bounded attempts. This is not an unlimited retry policy; per-attempt turn limits and run budgets remain enforced.

Tasks that ask Kristin to recruit participants, interview users, run surveys, conduct focus groups, or collect external feedback are rewritten into capabilities Kristin actually has:

- automated local interaction and accessibility checks;
- project-local test fixtures;
- an inspectable manual usability checklist such as `docs/testing/usability-checklist.md`;
- explicit instructions not to invent participant feedback.

Contradictory external design-tool and public-hosting instructions are replaced rather than appended. The original generated plan remains immutable; the corrected plan is stored as a new revision.

## Preserved safeguards

The repair does not broaden project permissions, tool allowlists, network policy, project boundaries, mutation evidence, stale-hash protection, or process execution privileges. Preloading uses the already configured local Ollama endpoint and exact selected model. Cancellation can terminate a wait but cannot authorize another action.
