# Kristin v1.7.0+170 — Model router, verifier, and convergence engine

V1.7 is the roadmap milestone that raises execution success without permitting uncontrolled retries. It is implemented on the consolidated typed-protocol, durable-kernel, Linux-sandbox, Prompt Studio 2, and Project Manager 2 foundation.

## Role-based routing

Model calls declare one of eight roles:

```text
router · specification · planner · executor
verifier · summarizer · research · safety reviewer
```

Routing evaluates data boundary, approved providers, model health, context capacity, task complexity, task-class benchmark history, latency, and cost. It cannot silently cross from local to remote processing, exceed the approved cost boundary, or select an unhealthy/open-circuit model. A stronger-model fallback is only offered when policy permits it and approval is required.

Route decisions and circuit state are durable in SQLite.

## Semantic progress

Each governed tool turn compares durable before/after facts:

- new artifacts;
- changed artifact hashes;
- new independent evidence;
- resolved and new errors;
- criteria satisfied or regressed;
- changed external state;
- valid plan revisions.

Repeated reads, duplicated errors, identical decisions, and no-op writes are not semantic progress.

## Convergence controller

Bounded non-progress escalates through deterministic actions:

```text
continue
→ compact and retry
→ require a different action
→ route to verifier
→ split task
→ ask user
→ offer an approved stronger model
→ fail with convergence evidence
```

No escalation widens tool, file, network, secret, provider, or data-boundary authority.

## Independent verification

The executor does not decide its own success. The verifier receives objective acceptance criteria, artifact facts, validator outcomes, hashes, and evidence identifiers. Unsupported completion claims fail before the work item can become successful.

Verification reports are append-only SQLite records.

## Phase budgets and context compaction

Routing, planning, execution, verification, repair, and summarization use distinct deterministic budgets. Context compaction removes duplicated history while retaining current requirements, unresolved errors, artifact state, criteria, and recent decision-relevant evidence.

## Executable gate

`tool/execution_intelligence_test.py` passes 40 deterministic cases covering:

- policy and schema rejection;
- local-first routing;
- provider and model approval;
- circuit opening, cooldown, half-open probing, and reset;
- semantic-progress classification;
- every convergence stage;
- no authority widening;
- false-success rejection;
- valid pre-existing artifacts;
- phase budgets;
- deterministic context compaction;
- CLI behavior.

## Runtime integration

`RunCoordinator` now records model-route decisions before provider work, updates circuit state after model outcomes, evaluates semantic progress after governed tool results, compacts context or changes strategy when stalled, and requires independent verification before accepting non-conversational completion with acceptance criteria.

## Criterion-scoped completion gate

The coordinator does not convert a broad “some objective evidence exists” condition into success. Each acceptance criterion is classified conservatively:

- verification criteria require a current successful governed verifier result;
- inspection criteria require a current governed observation hash;
- artifact criteria require a current artifact inspection and, when the work item promises implementation, a material mutation hash;
- a valid pre-existing artifact is accepted only when mutation is not required and current inspection proves its state;
- unknown criteria default to verification rather than permissive inspection.

Every accepted evidence item carries a criterion ID and a content/result hash or named validator. Stale, failed, non-independent, unscoped, and executor-summary evidence is ignored.

## Coordinator-enforced phase ceilings

A work-item attempt is capped by the execution phase budget even when the outer run budget is larger. The coordinator applies the model-request, tool-call, repair, and output-token ceilings and records the selected phase budget in the run event stream. Existing prompt-history limits remain stricter than the phase context ceiling.

## Explicit stalled-state outcomes

The convergence controller's plan-split, ask-user, and stronger-model stages are not informational labels. They produce typed terminal-to-the-attempt outcomes and durable events:

```text
work_item.plan_split_required          → task_split_required
work_item.awaiting_user                → agent_user_input_required
work_item.model_fallback_approval_required
                                       → model_fallback_approval_required
```

No stage silently continues, changes the plan, chooses another provider, or expands permissions.
