# Kristin Local Agent v1.0.2+102 budget and diagnostics hotfix

## Incident repaired

A work item could use its fixed 40-turn allowance, retry, use another 40 turns, and then begin a third attempt with the same run-level budget already exhausted. The observable sequence was:

```text
agent_turn_limit
work_item.started attempt=3
budget_model_requests
run.failed
```

The retry itself was therefore scheduled without enough reserved capacity to succeed. The UI Retry action also reused the failed run record, including spent counters and completed attempt counts.

## Execution changes

- `AutonomyBudget.forPlan` creates bounded budgets from plan size and complexity.
- Every attempt receives a fair share of remaining model requests and is capped at 24 turns by default.
- Each provider request consumes one budget unit before dispatch, including timeouts and provider failures.
- `work_item.retry_scheduled` and `work_item.retry_skipped` record the decision and budget snapshot.
- Budget exhaustion and nonrecoverable state errors are terminal; they are not retried automatically.
- Tool and mutation quotas are enforced only when another governed tool is dispatched, so a model may still return a final completion after collecting the last permitted evidence or applying the last permitted mutation.
- Repeating the same read-only tool call with the same result three times is classified as a stagnant agent loop and stopped.
- The model sees its current and remaining turn allowance and is instructed to complete or fail explicitly instead of continuing exploratory calls.
- A failed run returns `run_retry_required` when execution is requested directly.
- Retry creates a new linked run with `sourceRunId`, zero counters, zero attempts, and a newly calculated budget.

## New diagnostic events

```text
work_item.turn_budget_assigned
model.request_started
model.request_completed
model.request_failed
work_item.retry_scheduled
work_item.retry_skipped
agent.stalled_repeated_tool_outcome
run.retry_created
```

These events include bounded metadata such as run/work-item IDs, attempt and turn numbers, request duration, response hash and character count, error code, model identity, and budget counters. Complete model response bodies are not placed in the global event journal.

## Save all logs

The Logs workspace contains **Save all logs**. The resulting ZIP can contain:

- a readable `run-diagnostic-summary.md` with work-item, budget, evidence, and event timelines;
- diagnostic environment and settings fingerprints;
- all retained run records or a selected run/project focus;
- evidence metadata and bounded model-response previews;
- retained event and audit JSONL;
- bounded managed-process output;
- a README and per-entry SHA-256 manifest.

Source-like fields—including source, raw content, prompts, patches, replacements, and base64 payloads—are replaced by a hash and character count. Recognized secrets are redacted and long strings are bounded. This is defensive redaction, not a formal guarantee that no confidential context remains. Review every ZIP before sharing it.

CLI equivalent on Windows:

```powershell
.\kristin.cmd logs --export --run-id RUN_ID
```

Optional output path:

```powershell
.\kristin.cmd logs --export `
  --run-id RUN_ID `
  --output .\reports\kristin-diagnostics.zip
```
