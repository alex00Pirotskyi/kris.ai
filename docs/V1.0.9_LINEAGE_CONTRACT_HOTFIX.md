# Kristin Local Agent v1.0.9+109 lineage contract hotfix

## Reported behavior

On the user's configured Windows Flutter workstation, v1.0.8 completed the formatter, dependency-resolution, and analyzer gates successfully:

```text
dart format --output=none --set-exit-if-changed .  passed
flutter pub get                                      passed
flutter analyze                                     no issues
```

The native Flutter test suite then reported one failure in `source_contract_test.dart`:

```text
Expected VERSION_CONTROL.json to contain 81bc8384d545cd65
```

Both `kristin test --system` and `kristin test --release` reached `flutter test --no-pub` and failed on the same assertion. This confirms that the v1.0.8 SDK-environment repair worked; the remaining defect was release-lineage metadata.

## Root cause

The v1.0.6 workspace-boundary release retained a contract requiring the exact v1.0.5 path-hygiene parent SHA-256:

```text
81bc8384d545cd6586696ed3b58da315b596de042785ae9918ea4b2b427f18a2
```

When v1.0.8 rewrote `VERSION_CONTROL.json`, it preserved the user patch, workspace-boundary release, diagnostic bundle, and v1.0.7 parent, but omitted the v1.0.5 parent hash. The old Dart contract used an unscoped substring assertion, so the omission was detected only by the native Flutter suite.

No runtime, model, workspace-boundary, package-resolution, or Flutter analyzer defect caused this failure.

## Correction

V1.0.9 restores the missing ancestor and introduces a **structured transitive release lineage** in `VERSION_CONTROL.json`.

The ledger now preserves exact entries for:

- v1.0.5+105 path hygiene;
- v1.0.6+106 workspace-boundary canonicalization;
- v1.0.7+107 failed-run recovery;
- v1.0.8+108 SDK-environment compatibility;
- the merged user patch and diagnostic-bundle provenance.

A `lineageContract` object records that these ancestor versions must remain present across future heads.

## Structural validation

The Dart source-contract test now parses `VERSION_CONTROL.json` with `jsonDecode` and verifies exact version, role, and SHA-256 fields instead of searching for an unscoped text fragment.

The offline Python system fixture and release validator independently parse the ledger and reject:

- malformed or non-object JSON;
- a missing or reordered required-ancestor list;
- a missing ancestor release;
- a changed ancestor SHA-256;
- an incorrect current parent release;
- a future head that truncates the preserved lineage.

The v1.0.8 SDK subprocess profile and single-pass compile sequence remain unchanged:

```text
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
```
