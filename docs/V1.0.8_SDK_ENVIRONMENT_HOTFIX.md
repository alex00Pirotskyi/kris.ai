# Kristin Local Agent v1.0.8+108 SDK environment hotfix

## Reported behavior

For the v1.0.7 source on a configured Windows Flutter workstation, these commands passed when run directly:

```powershell
dart format --output=none --set-exit-if-changed .
flutter pub get
flutter analyze
flutter test
```

The same checkout then failed only when Flutter dependency resolution was launched through Kristin:

```text
Flutter dependency resolution: exit code 65 — Failed to update packages.
```

Release mode also failed inside its source-validation stage before reaching the already-proven analyzer and test gates.

## Root cause

Kristin intentionally launched project commands with a reduced environment. That environment preserved `PATH`, `USERPROFILE`, and temporary-directory variables, but omitted Windows and Dart/Flutter variables used to locate the Pub cache and enterprise network configuration, including `APPDATA`, `LOCALAPPDATA`, `PUB_CACHE`, proxy settings, and certificate-store overrides.

As a result, `flutter pub get` saw a materially different process environment under Kristin than it saw in the user's terminal.

Release mode additionally invoked `validate_release.py --skip-tests` without `--skip-sdk`. The source validator therefore ran another nested `flutter pub get` and analyzer pass before the CLI's own compile gates, duplicating work and inheriting the same reduced environment.

## Corrections

V1.0.8 introduces two explicit subprocess profiles:

- `default`: the existing narrow environment for ordinary project commands.
- `sdk`: the default environment plus bounded Dart/Flutter cache, SDK, proxy, certificate, Android, Java, Git, and XDG variables.

Flutter and Dart commands select the SDK profile automatically. Explicit compile gates also request it directly. Ordinary project commands do not receive Pub, proxy, certificate, or SSH-agent variables merely because they are present in the parent shell.

After the single explicit dependency-resolution gate succeeds, analyzer and test commands use `--no-pub` so they do not repeat package resolution.

Release source validation now always uses:

```text
validate_release.py --skip-tests --skip-sdk
```

The CLI then runs the SDK gates exactly once. The deterministic source packager uses the same source-only validation path.

Captured command output is redacted for common credentials, bearer values, API keys, and credentials embedded in proxy URLs before it is written to JSON, Markdown, or raw-log reports.

## Regression coverage

The offline system fixture now injects synthetic Windows cache, proxy, and certificate variables and verifies that:

1. `APPDATA` and `LOCALAPPDATA` survive the base environment.
2. `PUB_CACHE`, proxy, and certificate values reach only the SDK profile.
3. Flutter commands infer the SDK profile.
4. Ordinary Python commands retain the default profile.
5. Release source validation includes `--skip-sdk`.
6. Analyzer and test gates include `--no-pub`.

From a clean extraction on Windows:

